Mastering Async Python: Patterns and Pitfalls

Async Python has matured significantly since its introduction. This guide covers real-world patterns, common mistakes, and how to structure async code for maintainability and performance.

Jane Smith Senior Python Engineer at Acme Corp

Introduction

Python's asyncio library, introduced in Python 3.4 and significantly improved through 3.10 and 3.11, provides a foundation for writing concurrent code using coroutines. Unlike threading, asyncio uses cooperative multitasking — each coroutine yields control explicitly, allowing other coroutines to run.

This guide assumes familiarity with Python basics and focuses on practical patterns you'll encounter in production code. We'll look at real examples from web servers, database access, and external API clients.

Python version note: Examples in this article use Python 3.11+ syntax. For older versions, some features like asyncio.TaskGroup require backport libraries.

Understanding the Event Loop

The event loop is the core of any asyncio application. It runs asynchronous tasks, handles I/O events, and schedules callbacks. Understanding its mechanics helps avoid common mistakes. 

import asyncio
import time

async def slow_operation(name: str, delay: float) -> str:
    print(f"{name}: starting")
    await asyncio.sleep(delay)
    print(f"{name}: done after {delay}s")
    return f"{name}: result"

async def main() -> None:
    start = time.monotonic()

    # Sequential — total time ≈ sum of delays
    r1 = await slow_operation("task-1", 1.0)
    r2 = await slow_operation("task-2", 1.0)

    elapsed = time.monotonic() - start
    print(f"Sequential: {elapsed:.2f}s")  # ~2.0s

asyncio.run(main())

The sequential example takes ~2 seconds. By gathering tasks, we can run them concurrently: 

async def main_concurrent() -> None:
    start = time.monotonic()

    # Concurrent — total time ≈ max of delays
    results = await asyncio.gather(
        slow_operation("task-1", 1.0),
        slow_operation("task-2", 1.0),
    )

    elapsed = time.monotonic() - start
    print(f"Concurrent: {elapsed:.2f}s")  # ~1.0s
    print(results)

Common Patterns

Pattern 1: Structured Concurrency with TaskGroup

Python 3.11 introduced asyncio.TaskGroup, which ensures all tasks in a group are cancelled if any task raises an exception. This is safer than gather() for error handling. 

async def fetch_all(urls: list[str]) -> list[dict]:
    async with asyncio.TaskGroup() as tg:
        tasks = [
            tg.create_task(fetch_url(url))
            for url in urls
        ]
    return [t.result() for t in tasks]

Pattern 2: Semaphore for Rate Limiting

When making many concurrent requests, use a semaphore to limit concurrency and avoid overwhelming downstream services. 

async def fetch_with_limit(
    urls: list[str],
    max_concurrent: int = 10,
) -> list[bytes]:
    semaphore = asyncio.Semaphore(max_concurrent)

    async def fetch_one(url: str) -> bytes:
        async with semaphore:
            return await fetch_url(url)

    return await asyncio.gather(*[fetch_one(u) for u in urls])

Pattern 3: Producer-Consumer with Queue

For streaming data pipelines, use asyncio.Queue to decouple producers from consumers. 

async def pipeline(source: AsyncIterator[str]) -> None:
    queue: asyncio.Queue[str | None] = asyncio.Queue(maxsize=100)

    async def producer() -> None:
        async for item in source:
            await queue.put(item)
        await queue.put(None)  # Sentinel

    async def consumer() -> None:
        while (item := await queue.get()) is not None:
            await process(item)
            queue.task_done()

    await asyncio.gather(producer(), consumer())

Pitfalls to Avoid

  • Blocking the event loop: Never call blocking I/O or CPU-intensive operations directly. Use loop.run_in_executor() or asyncio.to_thread().
  • Fire-and-forget tasks: Always keep a reference to tasks created with asyncio.create_task(), or they may be garbage collected.
  • Ignoring cancellation: Catch asyncio.CancelledError only to do cleanup — always re-raise it.
  • Shared mutable state: Even in async code, concurrent access to shared state can cause bugs. Use locks or atomic operations.

Testing Async Code

Use pytest-asyncio for testing async functions. Mark async tests with @pytest.mark.asyncio or configure auto-mode: 

import pytest

@pytest.mark.asyncio
async def test_slow_operation() -> None:
    result = await slow_operation("test", 0.01)
    assert result == "test: result"

Conclusion

Async Python is a powerful tool for I/O-bound workloads. Key takeaways:

  1. Use TaskGroup for structured concurrency in Python 3.11+
  2. Use semaphores to limit concurrency for external resources
  3. Never block the event loop — use executors for blocking code
  4. Handle CancelledError correctly in cleanup code

For further reading, check the official asyncio docs and the Trio library for an alternative approach.
