# Protobuf 性能测试

zerodep protobuf 模块在小型、中型和大型消息结构下的编解码吞吐量测试。纯 Python proto3 实现，无 C 扩展。

!!! info "测试环境"
    - **平台:** x86_64 Linux
    - **Python:** 3.10.20
    - **工具:** pytest-benchmark 5.2.3（报告均值）

## 消息结构

| 标签 | 说明 |
|------|------|
| 小型 | 3 个字段：string + int32 + bool |
| 中型 | 5 个字段：uint64 + string + double + repeated[str] (4) + repeated[int32] (100) |
| 大型 | 6 个字段：uint64 + string + 50 个嵌套消息 + map[str,str] (20) + repeated[double] (100) + bool |

## 编码性能（均值）

| 消息规模 | 耗时 | OPS (Kops/s) |
|----------|------|--------------|
| 小型 | 4.6 μs | 215.4 |
| 中型 | 36.3 μs | 27.5 |
| 大型 | 294.2 μs | 3.4 |

## 解码性能（均值）

| 消息规模 | 耗时 | OPS (Kops/s) |
|----------|------|--------------|
| 小型 | 4.5 μs | 221.0 |
| 中型 | 50.7 μs | 19.7 |
| 大型 | 405.5 μs | 2.5 |

## 往返性能（均值）

| 消息规模 | 耗时 | OPS (Kops/s) |
|----------|------|--------------|
| 小型 | 9.5 μs | 105.0 |
| 中型 | 119.5 μs | 8.4 |
| 大型 | 712.3 μs | 1.4 |

## 字典转换（大型消息）

| 操作 | 耗时 | OPS (Kops/s) |
|------|------|--------------|
| `to_dict()` | 173.2 μs | 5.8 |
| `from_dict()` | 126.3 μs | 7.9 |

## 要点总结

- **小型消息编解码约 4.5 μs** -- 足够处理每请求元数据、RPC 头部和配置对象。
- **中型消息（约 100 个重复整数）往返低于 120 μs** -- 适用于批量负载和流式记录。
- **大型消息（约 50 个嵌套 + map + repeated）往返约 712 μs** -- 可用于配置对象和中等吞吐量管道。
- **字典转换与线格式性能相当** -- 同一大型消息 `from_dict()` 耗时 126 μs，而 `parse()` 耗时 405 μs，因为字典转换跳过了 varint/线格式编码。
- **纯 Python 实现** -- 无 C 扩展，无 `protoc`，无构建步骤。高吞吐量场景（>10K msg/s）建议使用带 C 加速的 google-protobuf。
