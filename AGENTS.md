# AGENTS.md

Zero-dependency, single-file Python module library. Each module lives in its own directory, uses only stdlib, and is designed to be copied directly into projects via the `zerodep` CLI.

## Key Commands

All module operations go through the `zerodep` CLI — do not replicate their behavior manually.

```bash
# Module management
zerodep list                     # List all modules by category
zerodep info <module>            # Show module metadata (version, deps, tier)
zerodep new <name> --category <cat> --tier <tier>  # Scaffold new module
zerodep add <module> [module...] # Copy module files to target directory
zerodep update <module>          # Update existing module files

# Version & release
zerodep bump [modules...]        # Bump module versions (--patch|--minor|--major)
zerodep version-check            # Detect modules modified since declared version
zerodep version-check --strict   # Same, but exit 1 if any need bumping

# Manifest & dependencies
zerodep manifest                 # Regenerate manifest.json from source
zerodep dep-graph [module]       # Show dependency graph
zerodep dep-check [modules...]   # Test changed modules + downstream dependents
```

### Makefile shortcuts

```bash
make test                  # All correctness tests
make test-<module>         # Single module correctness test
make benchmark             # All benchmarks
make benchmark-<module>    # Single module benchmark
make lint                  # ruff check
make fmt                   # ruff format
make manifest              # Regenerate manifest.json
make version-check         # Detect uncommitted version bumps
make dep-graph             # Show dependency graph
make dep-check             # Test changed modules + dependents
make docs-index            # Generate module index for EN/ZH docs
```

## Module Structure

Every module follows this layout:

```
<module>/
├── <module>.py                    # Implementation (single file, stdlib only)
├── test_<module>_correctness.py   # Tests against reference library
├── test_<module>_benchmark.py     # Performance benchmarks
└── conftest.py                    # Optional fixtures
```

### Frontmatter

Each module file starts with a PEP 723-style metadata block:

```python
# /// zerodep
# version = "0.3.1"
# deps = ["httpclient"]
# tier = "subsystem"
# category = "serialization"
# ///
```

- **version**: SemVer — bumped via `zerodep bump`, never edit manually
- **deps**: inter-module dependencies — must match actual imports
- **tier**: `simple`, `medium`, or `subsystem`
- **category**: one of `network`, `protocol`, `serialization`, `validation`, `text`, `config`, `terminal`, `crypto`, `image`, `process`, `storage`, `devtools`

## Non-Obvious Rules

- **No third-party imports** in module source files. Only Python stdlib. Test files may import reference libraries for comparison.
- **Do not edit `manifest.json`** — it is auto-generated by `zerodep manifest`. After changing any module metadata, run `make manifest`.
- **Do not manually edit version in frontmatter** — use `zerodep bump`. It tracks content hashes to detect actual changes and prevent double-bumping.
- **Inter-module deps must be declared** in the `deps` frontmatter field. Undeclared cross-module imports will break `zerodep add` dependency resolution.
- **Versioning scheme**: project uses CalVer (`YYYY.M.D`), individual modules use SemVer.
- **After creating a new module** with `zerodep new`, you must run `make manifest` and `make docs-index` to register it.

## Testing

- Correctness tests compare zerodep output against reference libraries (PyYAML, httpx, pydantic, etc.)
- Benchmarks use `pytest-benchmark` for performance comparison
- Run `make dep-check` after modifying a module to ensure downstream dependents still pass

## Boundaries

### Allowed without asking
- Read files, run tests, run lint/format
- Run `zerodep info`, `zerodep list`, `zerodep dep-graph`

### Ask first
- Adding new inter-module dependencies (modifying `deps` in frontmatter)
- Deleting or renaming modules
- Modifying CI workflows or release configuration

### Never
- Import third-party packages in module source files
- Manually edit `manifest.json`
- Force push to master
